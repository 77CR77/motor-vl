# Запуск сайта на reg.ru — пошагово

Документ для владельца сайта. Всё, что нужно сделать руками, собрано здесь
по порядку. Домен: **motor-vl.ru**. Хостинг: виртуальный, reg.ru, PHP.

Важно: на этом же домене сейчас работает **старый сайт на Yii2** (PHP + база
MySQL). Новый сайт его заменяет, поэтому первым делом — бэкап.

---

## Шаг 1. Бэкап старого сайта — три части

Публичные страницы я уже сохранил: `~/motor-vl-backup-2026-08-19`
(65 страниц, открываются в браузере). Остальные две части может сделать
только владелец доступов.

### 1.1. Файлы сайта (по FTP)

Это PHP-код старого сайта: шаблоны, настройки, админка. В браузере их не видно.

1. Панель reg.ru → раздел **Хостинг** → **FTP-доступ**. Там хост, логин и пароль.
2. Скачать [FileZilla](https://filezilla-project.org/) (бесплатно) либо открыть
   **Файловый менеджер** прямо в панели.
3. Найти папку сайта — обычно `/var/www/USER/data/www/motor-vl.ru/`
   (у reg.ru встречается и `public_html`).
4. **Скачать эту папку целиком** на компьютер, например в
   `~/motor-vl-backup-2026-08-19/server-files/`.

Папку `media` внутри можно пропустить — фото и видео уже лежат
в `~/Desktop/motor-vl-photos`.

### 1.2. База данных (из панели)

Каталог, цены, характеристики и номера моторов старого сайта лежат в MySQL.
Без этой выгрузки откат невозможен, даже если файлы целы.

1. Панель reg.ru → **Хостинг** → **Базы данных** → **phpMyAdmin**.
2. Войти, слева выбрать базу сайта (обычно одна, с именем вида `u1234567_motorvl`).
3. Вкладка **Экспорт** → способ «Быстрый», формат **SQL** → **Вперёд**.
4. Скачанный файл `.sql` положить рядом с бэкапом файлов.

### 1.3. Проверка, что бэкап полный

В папке бэкапа должно быть три вещи:

- [ ] `server-files/` — код старого сайта с FTP
- [ ] `база.sql` — выгрузка MySQL
- [ ] страницы, которые я сохранил (уже есть)

Пока все три галочки не стоят — ничего на хостинге не менять.

## Шаг 2. Отложить старый сайт, а не удалять

Самая быстрая страховка. По FTP **переименовать** папку старого сайта:

```
motor-vl.ru  →  motor-vl.ru-OLD
```

Затем создать пустую папку с прежним именем — в неё пойдёт новый сайт.
Если что-то не заработает, откат занимает полминуты: удалить новую папку
и вернуть старой имя обратно.

Старый сайт при этом перестанет открываться — это нормально и ожидаемо.

---

## Шаг 3. Залить новый сайт

Из папки `~/motor-vl-repo` в корень сайта нужны:

```
*.html            страницы
css/  js/         стили и скрипты
data/             каталог (motors.json, brands.json и остальное)
images/           логотип и иконки сайта
media/            фото и ВИДЕО моторов
api/              серверная часть (PHP)
private/          пустая папка под заявки
panel/            панель управления
```

Не нужны на хостинге: `tools/`, `.git/`, `.vscode/`, `.claude/`, `README.md`,
`DEPLOY.md`.

### Про видео — отдельно

Ролики (3.3 ГБ, папки `media/*/video/`) в git не хранятся: репозиторий такого
объёма не выдержит. Поэтому **видео заливаются по FTP один раз, руками**.
Дальше автодеплой их не трогает — они просто лежат на сервере.

Заливать лучше вечером и не выключать компьютер: на обычном интернете
3.3 ГБ уходят за 1–3 часа. В FileZilla это очередь, которая переживает обрывы:
если связь упала, нажать «Возобновить».

---

## Шаг 4. Настройки и права

1. Скопировать `api/config.example.php` в `api/config.local.php`
   (можно прямо на сервере, через файловый менеджер).
2. Вписать три значения:
   - `admin_password` — новый пароль панели;
   - `telegram_token` — токен от @BotFather (старый отозвать через `/revoke`);
   - `telegram_chat_id` — уже вписан: `-5393279907`.
3. Права доступа (в FileZilla: правой кнопкой → Права доступа к файлу):
   - папки `data`, `media`, `private` → **755**
   - файл `data/motors.json` → **644**

## Шаг 5. Проверка

Открыть в браузере:

```
https://motor-vl.ru/api/selftest.php?password=НОВЫЙ_ПАРОЛЬ
```

Страница по пунктам покажет: версию PHP, наличие настроек, права на запись,
отвечает ли бот Telegram. Отдельно проверит **закрыта ли папка с заявками**
от посторонних — это важно, потому что там телефоны клиентов, а сервер работает
на nginx, который может игнорировать файл `.htaccess`.

Если все пункты зелёные — оставить тестовую заявку на сайте. Она должна прийти
в чат менеджеров и появиться в панели `/panel`.

## Шаг 6. Автообновление с GitHub

Сам механизм уже готов — файл `.github/workflows/deploy.yml`. Осталось выдать
ему доступ к хостингу. Четыре значения задаются один раз.

### 6.1. Где взять данные FTP

Панель reg.ru → **Хостинг** → **FTP-доступ**. Оттуда нужны:

| Что | Пример | Где смотреть |
|---|---|---|
| Хост | `ftp.motor-vl.ru` или IP-адрес | в разделе FTP-доступ |
| Логин | `u1234567` | там же |
| Пароль | | там же (можно сменить кнопкой) |
| Путь к сайту | `/motor-vl.ru/` | видно в FileZilla, когда открыта папка сайта |

Путь — это то, что стоит в адресной строке FileZilla, когда вы находитесь
в папке с `index.html`. Часто это `/motor-vl.ru/` или `/public_html/`.

### 6.2. Куда их вписать

На GitHub: репозиторий → **Settings** → **Secrets and variables** → **Actions**
→ кнопка **New repository secret**. Создать четыре штуки, имена строго такие:

```
FTP_SERVER      ftp.motor-vl.ru
FTP_USERNAME    u1234567
FTP_PASSWORD    пароль от FTP
FTP_DIR         /motor-vl.ru/
```

GitHub прячет их: после сохранения значение нельзя посмотреть даже владельцу
репозитория. Присылать эти данные кому-либо не нужно.

### 6.3. Первый запуск

Вкладка **Actions** → слева **Deploy to reg.ru** → кнопка **Run workflow**.
Через пару минут появится галочка или крестик. Если крестик — открыть запись,
там будет видно, на чём споткнулось (чаще всего неверный `FTP_DIR`).

Дальше всё само: правка → пуш в `main` → через минуту сайт обновлён.

### Что автодеплой НЕ трогает

- `media/**/video/**` — 3.3 ГБ роликов, они залиты один раз вручную;
- `api/config.local.php` — пароль и токен бота живут только на сервере;
- `private/**` — заявки клиентов.

Это защита от главной ошибки: чтобы выкладка сайта не стёрла настройки
и не удалила накопившиеся заявки.

---

## Если что-то пошло не так

1. По FTP удалить папку нового сайта.
2. Вернуть `motor-vl.ru-OLD` → `motor-vl.ru`.
3. Старый сайт снова работает.

База при этом не пострадала — новый сайт её не использует вообще.
